# Design a plan people can use

## Make the first screen useful

Show the goal, the next action, and the nearest meaningful milestone before a
long explanation or directory of links. A person should understand both what the
plan is for and what to do next without scrolling. Put working records within
reach of that summary; move detailed scope and resources into their own sections,
record bodies, or pages.

Use a short descriptive title and a meaningful colored icon on the home and its
record pages. Carry the same icon choices into mentions. Choose one restrained
accent palette appropriate to the subject; reserve warning colors for real risks.
A shallow cover can give an event or trip a recognizable identity. Do not let a
large cover or decorative callout push the useful work below the first screen.
Use original or authorized artwork, and keep proposed creative distinct from real
photos, confirmed assets, and booking evidence.

For a desktop overview, use full width when side-by-side context and records
benefit from it. A narrow action/navigation column beside a wider working view
suits events and recurring content. A short summary beside a status chart suits a
launch only when the chart answers a useful question from actual records. A calm
single column suits a small personal plan. Use readable prose widths on detail
pages. Columns should remain understandable when stacked on a narrow screen.

## Give each kind of work its own place

| Plan                         | Useful entrance                                                    | Deeper work                                            |
| ---------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------ |
| Event                        | Next booking decision, date and budget context, upcoming task rows | Run sheet, invitation drafts, private guests           |
| Trip                         | Next departure or booking to confirm, itinerary ordered by date    | Booking details, preparation checklist, budget         |
| Job search                   | Follow-ups due, next interview, application stages                 | Role requirements, tailored materials, interview notes |
| Launch                       | Release decision and nearest milestone, open deliverables          | Workstreams, readiness checks, support material        |
| Campaign or content calendar | Campaign cards or the next content to review                       | Production board, publishing calendar, complete drafts |
| Move or other personal goal  | Next dependency and dated checklist                                | Quotes, packing or preparation lists, instructions     |

Use galleries when cards provide meaningful context or visual previews, boards
when stage changes matter, tables when comparing fields matters, and calendars
when dates matter. Do not add all views by default. Keep undated items reachable
outside date-only views. Hide repeated database titles and redundant chips.
Wrap names and retain readable dates, status, and the fields needed for decisions.

For database pages, show the important properties near the title: status, due or
scheduled date, responsible person when known, and the relation to the plan.
Keep secondary fields in details. Do not repeat the entire property panel as
prose. The body supplies the reasoning, instructions, draft, and open questions.

## Keep one connected system

A plan home contains a compact summary and focused views of the underlying work,
not duplicate tables that must be updated separately. Shared task collections
need an exact plan filter. Keep stable destinations recognizable in the sidebar
and provide a route back from every detail page.

Typical task properties are Name, Status, Owner, Due, and Plan; add Dependencies,
Type, or a source link only when useful. Dependencies should point to real records.
Keep long notes in page bodies. Use native date, status, number, and relation types
so views remain useful as work changes.

Provide creation actions or database templates where repeated entry benefits
from them, such as a new application or a weekly content brief. A button must
perform its named action, and a template must produce the right properties and
body. Do not present a decorative label as a working control.

Use the overview for orientation and details for execution. Avoid filling every
section to make the page appear complete: an explicit missing venue is useful;
a fictitious venue or an empty “Resources” gallery is not.
