# Evaluate Make a plan

Use the [shared evaluation protocol](../../evaluations.md) in isolated stateful
fixtures. These scenarios are specifications, not claims of completed runs.

| Scenario                                                   | What it checks                                                                                |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| [Event from notes](event-from-notes.json)                  | Initial private delivery, dependencies, substantive drafts, budget uncertainty, guest privacy |
| [Extend a content calendar](extend-existing-calendar.json) | Reuse, preserved publication state, undated work, scoped structure                            |
| [Organize a trip](trip-facts-and-costs.json)               | Booking evidence, local times, estimated versus confirmed costs, useful preparation           |

For each created plan, inspect the rendered home and a detail record. The first
screen should expose a meaningful next action and working information; titles,
dates and properties must be readable. Follow home → record → related work → home.
Check both desktop and narrow layouts. Grade native relations, filter membership,
and factual fidelity from persisted state as well as appearance. A pretty overview
with empty records or invented commitments fails.

Also check selection with all installed skills: a quick packing list, a single
post rewrite, destination comparison, and an engineering spec breakdown should
not trigger an unnecessary new plan. A requested event, trip, move, or job-search
system should. Where a specialist also fits, accept that route if it produces the
requested outcome without duplicate systems.
