# Page layout

## The first screen of the plan home

Without scrolling, the person should see:

1. **The goal and its date,** in one line, under a short title with a meaningful icon.
2. **The next action,** in a single callout: who does what, by when.
3. **The nearest milestone and any real risk.** Use a warning color only for real risks.
4. **The working view of tasks:** open work, sorted by due date, with title, status, owner and due date readable.

Put the rest below that: milestones (outcome, done when, owner, date), what the plan needs (people, budget, materials, tools), risks, and a **Status** section that check-ins update.

## Views

Add views that answer a real question, never all of them:

| Question                     | View                                                                          |
| ---------------------------- | ----------------------------------------------------------------------------- |
| What's stuck or in progress? | Board by status                                                               |
| What's due when?             | Calendar by due date, plus a "Needs a date" view so undated work isn't hidden |
| How does the work overlap?   | Timeline (launches and team projects)                                         |
| What's mine?                 | "My tasks" filtered to the current person (team projects)                     |
| What's done?                 | Done or Completed, kept separate from open work                               |

- **Project views of a shared Tasks database must filter by the project relation,** not by a name match.
- **Hide repeated database titles** and keep only the properties needed to act.

## Task pages

- **Near the title:** Status, Due, Owner and Project.
- **In the body:**
  - the next step
  - what "done" means
  - the real content: a draft, run sheet, captions or checklist
  - open questions

  Mark new creative work as a draft.

- **Every page links back to the plan home.**

## Style

- **Look:** one restrained accent color, and a shallow cover only when it gives an event or trip an identity.
- **Columns:** a narrow action and navigation column beside a wide working view suits events and content. A single column suits a small personal plan. Columns must still read well when stacked on a narrow screen.
- **Leave out:** decorative widgets, empty "Resources" sections, and anything made up to make the page look complete. An explicit "Venue: not chosen yet" is useful.
